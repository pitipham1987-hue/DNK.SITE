# DNK's House — Copilot Instructions

Landing page for DNK's House (AI Agents for customer support). Static vanilla site: **no frameworks, no build steps, HTML5 + CSS3 + Vanilla JS only**.

## Core Constraints

### Tech Stack
- **HTML5 + CSS3 + JavaScript (vanilla)** — no React, Vue, Svelte, build tools, or dependencies beyond what's checked in
- **Vanilla JS patterns:** IIFE modules in `assets/js/`, `IntersectionObserver` for scroll animations, no jQuery or DOM libraries
- **Server:** Python HTTP server (`python -m http.server 8000`) or similar static host

### CSS Architecture
1. Always load in order: `tokens.css` → `base.css` → `components.css`
2. **No hardcoded colors/spacing:** Every color and spacing value must reference CSS custom properties (`--color-*`, `--space-1..8`, `--radius-*`) from `tokens.css`
3. **Section color system:** Each `<section>` carries one of: `section-blue`, `section-pink`, `section-cream`, `section-white`, `section-black`
4. Navigation: update nav/footer in **all 4 files** when changed: `index.html`, `pages/about.html`, `pages/contact.html`, `pages/services.html`

### HTML Structure
- Semantic HTML5 (`<header>`, `<nav>`, `<main>`, `<section>`, `<footer>`)
- Accessibility: heading order consistent (no h1→h3 jumps), focus states, sufficient color contrast
- Responsive mobile-first: test at ~390px (mobile), ~768px (tablet), ~1280px+ (desktop)

### Animation & Interaction
- **Every `<section>` must have scroll reveal:** fade-in + slight Y-axis translate when scrolled into view
- Use `IntersectionObserver` + CSS `transition` with class toggle (e.g., `.is-visible`)
- **Respect `prefers-reduced-motion: reduce`** — disable/reduce animations for users who set this preference
- No heavy animation libraries (GSAP, AOS, etc.) unless explicitly requested

## Design Reference

- **Visual standard:** [weav.com_RS.png](weav.com_RS.png) — compare layout, color blocks, spacing, and typography after major changes
- **Screenshot-verify:** After editing `components.css` or a full `<section>`, take a screenshot of the running site and compare side-by-side with the reference
- **Typography:** Be Vietnam Pro (Google Fonts), headings large + bold + tight line-height, body ~16–18px with 1.5–1.6 line-height
- **Color blocks:** strong contrast between sections (blue → pink → cream → white → black), no subtle gray washes

## Content & Brand

- **Company:** DNK's House — AI Agents for customer support, **not "Weav"** (reference design only)
- **Language:** Vietnamese (tiếng Việt) unless otherwise specified
- **Tagline:** "Automate the volume, humanize the interaction" — tự động hoá khối lượng, nhân tính hoá tương tác
- **Tone:** confident, benefit-focused, not overly technical

## Asset Paths

- From `index.html` (root): `assets/css/`, `assets/js/`, `assets/images/`
- From `pages/*.html`: `../assets/css/`, `../assets/js/`, `../assets/images/`
- **Never use absolute paths or `file://` URLs**

## Supabase & Admin

- **Keys:** Only `VITE_SUPABASE_ANON_KEY` in browser/client code. **Never commit `service_role` key.**
- **Auth:** Google OAuth only (no email/password signup)
- **Admin access:** `public.profiles.role = 'admin'` only
- **Blog:** `/pages/blog.html?slug=<slug>` for post detail; `#insights` section on homepage shows latest 3 published posts
- **Admin panel:** `/admin/index.html` — create/draft/publish/delete posts, upload avatar images

## Before Marking Work Complete

1. ✅ **Design match:** Screenshot the running site, compare against [weav.com_RS.png](weav.com_RS.png) — note any blatant layout/color/spacing mismatches
2. ✅ **Mobile check:** Test in browser at ~390px viewport — all sections readable, no overflow
3. ✅ **Sync 4 files:** If nav/footer changed, verify updates in `index.html`, `pages/about.html`, `pages/contact.html`, `pages/services.html`
4. ✅ **Scroll animation:** Verify new sections fade in when scrolled (toggle DevTools animation slowdown to watch)

## Decision Log

- Vanilla JS + vanilla CSS by design — team prefers direct control over frameworks
- Supabase + Google OAuth for admin system (lightweight, no server to maintain)
- RLS policies enforce all security (no `service_role` in client)
- No compaction/minification in dev — deploy with a CDN minifier if needed
